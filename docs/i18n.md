# Internationalization

Read this before adding or changing any text a user can see.

## How it works

There are two layers, because Chrome's own `chrome.i18n` follows the browser language and cannot be switched at runtime.

| Layer | Files | Language follows |
| --- | --- | --- |
| Interface text | `src/locales/en.js`, `src/locales/zh-CN.js`, read through `src/shared/i18n.js` | the `uiLanguage` setting |
| Extension name, description, toolbar title | `extension/_locales/<locale>/messages.json`, referenced as `__MSG_key__` in the manifest | the browser, always |

`uiLanguage` is `auto` (the default), `en` or `zh-CN`. `auto` picks the locale that matches the browser language and falls back to English. The popup and the settings page both have a selector for it; in-player overlays follow the same setting.

## API

```js
import { t, plural, label } from '../shared/i18n.js';

t('translation.loading')                      // plain string
t('skins.switched', { name })                 // `{name}` placeholders
plural('vocabulary.count', words.length)      // picks `vocabulary.count.one` / `.other`
label('action', action)                       // registry item name in the current locale
label('character', character, 'description')
```

Static HTML is filled by `src/ui/localize.js`:

```html
<span data-i18n="skins.label">Caption skin</span>
<input data-i18n-attr="placeholder:vocabulary.search;aria-label:vocabulary.search">
```

`data-i18n` replaces the element's whole text, so give translated text its own element; do not put it next to child elements. Keep the English text in the HTML as well, so the page reads correctly before scripts run.

## Rules

- Never write user-visible text inline in JavaScript or HTML. Add a key and use it.
- English is the source locale. Every key exists in `en.js`; add the same key to `zh-CN.js` in the same change. A key missing from a locale falls back to English.
- Keys are `namespace.name`. Plural namespaces hold interface text (`skins.label`, `actions.list`). Singular namespaces translate registry items by id (`skin.<id>`, `character.<id>`, `character.<id>.description`, `action.<id>`, `reaction.<id>`).
- Registry items carry their English `name` (and `description`) in their own module. `en.js` has no entry for them; other locales override them under the singular namespace. This keeps "add an action" a one-file change, with the translation optional.
- Plural keys end in a CLDR category. English needs `.one` and `.other`; Chinese needs only `.other`.
- Text that depends on the locale must be re-rendered when the locale changes. In the popup and settings page, `bindSettingsForm({ onLocale })` calls back after a switch. In the content script, every feature's `update(settings)` runs after `setLocale`, so set labels there.

## Errors

The background worker does not know which language a page is showing, so errors cross the message boundary as codes.

```js
throw new AppError('unavailable', { status: response.status });   // src/shared/errors.js
```

`request()` in `src/shared/messages.js` turns the code into `t('error.<code>', params)` on the receiving page. Add the `error.<code>` key to both dictionaries when you add a code. Errors meant for developers, such as registry validation, stay as plain English `Error`s.

## Adding a locale

1. Add `src/locales/<id>.js` with the keys from `en.js`, plus overrides for registry items.
2. Register it in the `locales` array in `src/shared/i18n.js`. It appears in the language selectors automatically.
3. Add `extension/_locales/<id with underscore>/messages.json` with the same three keys as `en`.

## What is not translated

- Translation target languages are listed by their own names in `src/shared/settings.js`.
- Word collection and caption expressions match English captions only. See [captions.md](captions.md) and [mascot.md](mascot.md).
